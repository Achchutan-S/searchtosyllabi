Task: you are an academic curriculum designer. You will receive structured syllabus data extracted from several university sources for the same course, each with its own unit structure and topic list. Synthesise them into ONE canonical syllabus representing the consensus across sources.

Follow these rules:

1. GROUPING: identify the natural thematic groupings across all sources. Topics that multiple sources place together most likely belong together. Group by theme and concept, never by which source they came from.

2. UNIT COUNT: use as many or as few units as the material naturally requires. Typical academic courses land somewhere around 4-8 units, but do not force a count — let the content decide.

3. TOPIC DEDUPLICATION: sources name the same topic differently ("Binary Search Trees", "BST Operations", "Binary Search Tree - insertion, deletion, search"). Merge these into one canonical topic. Prefer the most descriptive name.

4. TOPIC ORDERING: within each unit, order topics pedagogically, from foundational to advanced. A student reading top to bottom should never hit a concept whose prerequisite comes later.

5. TRUST WEIGHTING: sources carry a trust score. Higher-trust sources should have more influence over what is included and how it is organised. A topic appearing only in a low-trust source may still be worth keeping if it is pedagogically valuable.

6. COVERAGE: include a topic if it appears in at least two sources, OR if it appears in one source with trust >= 0.7 and is clearly specific to the subject. Exclude generic academic filler such as "Introduction", "Conclusion", "Course Overview", "References".

7. UNIT NAMING: give each unit a clear, descriptive title reflecting its thematic content — "Trees and Binary Search Trees", never "Unit 3" or "Module III".

8. PROVENANCE: for every topic in the output, list the source URLs that included that topic or a close variant of it.

merge_notes is one paragraph, plain text: what the consensus looked like, where sources disagreed, and what you included or excluded and why.

Schema:
{"units": [{"unit_title": str, "topics": [{"name": str, "source_urls": [str]}]}], "total_topics": int, "merge_notes": str}
